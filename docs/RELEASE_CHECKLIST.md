# Проверка релиза Vikify

## Сборка и обновление

- Сохранить предыдущие исходники и установочный файл, проверить контрольные суммы резервной копии. Увеличить versionCode для каждой поставляемой версии.
- Собрать обычный ARM64 release с постоянным ключом по инструкции [RELEASE_SIGNING](RELEASE_SIGNING.md). Сначала выполнить модульные тесты и release Lint. Собрать APK и AAB с включённым R8.
- Проверить AAB через bundletool validate и jarsigner. Проверить APK через apksigner. Сверить сертификат, пакет, minSdk, targetSdk, отсутствие debug-флага, тестовых корней и действующих реквизитов подписок. Сохранить контрольные суммы и приватную копию R8 mapping.
- Проверить выравнивание каждого нативного ELF и установку split APK из AAB. Проверить туннель на настоящем ARM64, в том числе на устройстве с размером страницы 16 КБ.
- Проверить обновление поверх предыдущей версии с тем же сертификатом. Для перехода с debug на release сначала сохранить ссылку пользователя и согласовать переустановку.

## Пользовательский сценарий

- Добавить подписку из буфера, через камеру и выбор изображения. Проверить временный отказ в разрешении камеры. Проверить ошибку TLS и замену недоступной подписки.
- До первого подключения показать отдельное раскрытие обработки трафика. Проверить отмену, ссылку на политику, отказ в системном VPN-разрешении и явное принятие.
- Для каждого рабочего профиля подтвердить DNS и HTTPS из другого UID при активной сети VPN. Проверить остановку, смену профиля, уведомление и отзыв согласия. Вернуть первоначальный выбранный профиль и отключить VPN.
- Проверить маленький экран, поворот, крупный шрифт, тёмный фон и навигацию с TalkBack. Согласие и политика должны прокручиваться до последней кнопки.

## Канал распространения

- Для основного F-Droid проверить точный рецепт в актуальном CI, получить совпадение с опубликованным APK через проверку переноса подписи, сохранить `Binaries` и `AllowedAPKSigningKeys`. Закрытый ключ издателя в CI не передавать. Заявку отправлять после успешной проверки; принятие каталогом подтверждать отдельно.
- Согласовать README основной ветки, политику, документацию сборки и сведения о сопровождении. Сохранить неизменяемые теги и APK ранее выпущенных версий. Исторические отчёты отмечать датой и версией, не представлять их как свежие тесты.
- Для собственных загрузок разместить подписанный APK, политику, лицензии, отпечаток сертификата и SHA-256. Проверить скачивание и обновление через фактический канал. Сохранить независимую восстановимую копию ключа.
- Перед Google Play подтвердить аккаунт организации, издателя, контакт и серверные практики обработки данных. Разместить политику на публичном URL, собрать версию с этим адресом, проверить доступ с телефона без входа. Подготовить App Access, Data safety, VpnService, декларацию foreground-сервиса, возрастной рейтинг, аудиторию и материалы карточки. Предоставить отдельный демонстрационный доступ для ревью.
- Публикация политики и обновление Galaxy отражены в [отчёте по сборке 16](RELEASE_1.4.1_BUILD16.ru.md). Проверки пяти профилей сохранены в [отчёте сборки 15](RELEASE_1.4.0_BUILD15.ru.md), расширенная проверка Android 16 — в [отчёте сборки 14](RELEASE_REPORT_1.4.0.ru.md).
